## Executive Diagnosis

V6.6 has positive gross edge but negative net-after-brokerage outcome.

- Gross PnL: `+769,418.40`

Core issue: strategy is over-trading low-quality opportunities where gross per-trade edge is smaller than round-trip cost.

### 5A) HMA robustness blueprint (new)

Use HMA as a full quality framework, not only direction.

1. Slope gate (trend quality):
- Compute `slope9 = (hma9_t - hma9_t-1) / atr_5m`.
- Compute `slope21 = (hma21_t - hma21_t-1) / atr_5m`.
- Long: require both positive and minimum strength.
- Short: require both negative and minimum strength.
- Start test ranges:
- `abs(slope9) >= 0.03`
- `abs(slope21) >= 0.015`

2. Crossover age gate (avoid too fresh or too stale):
- Define `cross_age_bars` as bars since `sign(hma9-hma21)` changed.
- Reject immediate post-cross noise and late exhausted trends.
- Start test window:
- `2 <= cross_age_bars <= 12`

3. Price-vs-HMA structure gate:
- Long: candle close above both `hma9` and `hma21`.
- Short: candle close below both `hma9` and `hma21`.
- Add persistence:
- Last `2` closes must satisfy same rule.

4. HMA distance gate:
- Keep the existing gap sweet spot:
- `0.04% <= hma_gap_pct <= 0.18%`
- Add price stretch control:
- `price_hma9_dist_atr = abs(close-hma9)/atr_5m`
- Reject over-extended and too-flat entries.
- Start test window:
- `0.05 <= price_hma9_dist_atr <= 0.60`

5. Candle close confirmation gate:
- Body strength filter:
- `abs(close-open)/(high-low) >= 0.35`
- Directional close filter:
- Long: close in top `40%` of candle range.
- Short: close in bottom `40%` of candle range.

6. Recross stability gate:
- Reject if `hma9-hma21` flipped in last `N` bars.
- Start test:
- No recross in last `3` bars.

7. Optional HMA quality score (for capital scarcity ranking):
- Build `hma_quality_score` (0-100) from slope, age, distance, close confirmation.
- Admit only `score >= threshold` when capital is constrained.
- Suggested weights:
- slope `35%`, age `20%`, distance `25%`, candle close `20%`.

8. Practical implementation order:
- Step 1: keep only `gap + structure + 2-close confirmation`.
- Step 2: add slope gate.
- Step 3: add cross-age and recross filters.
- Step 4: use HMA quality score for queue ranking under low capital.

## Why So Many Loss Trades?

Main drivers:

- High count of hard-stop outcomes (`~34%` of trades) with full-risk losses.
- Too many low-edge entries where expected move does not cover fixed trading costs.
- Mid-session and neutral-regime entries have weak expectancy.
- Significant long-side drag compared to short side in this dataset.
- Capital bottleneck causes selection pressure; currently not quality-ranked strongly enough at entry.

## Optimization Plan for Next Iteration (v6.6.1)

### Priority 0 (fastest, highest impact)

1. Add regime filter:

- Skip `NEUTRAL` regime entries.

2. Add session filter:

- Disable `MID_1030_1200`.
- Keep `OPEN` and `LUNCH` initially; test `AFTERNOON` separately.

3. Add HMA-gap quality filter:

- Trade only when `0.04% <= hma_gap_pct <= 0.18%`.
- Also implement section `5A` core gates:
- slope gate
- cross-age gate
- 2-candle close confirmation
- price-vs-HMA structure

4. Add cost-to-risk viability gate:

- Estimate round-trip brokerage at entry.
- Require `estimated_cost_in_R <= 0.10R` (or stricter after testing).

5. Add minimum practical position filter:

- Enforce minimum `notional_at_entry` (test `100k` and `250k`) OR minimum `risk_amount`.
- Goal: remove trades where cost dominates realized edge.

### Priority 1 (risk and exit tuning)

1. Reduce STOP_HARD bleed:

- Add one more confirmation constraint before entry (example: require HMA gap persistence for N bars).
- Apply lower risk multiplier in weak states (neutral-like volatility windows if they remain enabled).

2. Improve trail efficiency:

- Current trail winners are too often tiny.
- Test breakeven/trailing arm thresholds to reduce micro-profit exits that cannot beat costs.

### Priority 2 (portfolio allocation logic)

1. Quality-ranked admission under capital scarcity:

- When capital/slots are limited, rank candidates by quality score (gap quality, regime, vix state, sector expectancy) instead of scan-order first.

2. Sector throttling:

- Temporarily downweight or block sectors with persistent negative net-after-cost profile.

## Bottom Line

v6.6 does not have a direction problem first; it has an entry-quality and cost-efficiency problem.  
The fastest path to improvement is to **trade less but higher quality** using regime/session/HMA-gap/cost-in-R gates, then upgrade capital-constrained candidate ranking.
