# V6.2 Strategy Improvement — Suggested Changes

## Executive Summary

The strategy is marginally profitable but fragile. Across three engine versions the
core problem is the same: **too many low-conviction trades enter on the wrong side
of the market**. The tables below quantify the damage and propose specific, testable
changes to the Sector Scoring and Signal Grading subsystems.

## 2 Root-Cause Analysis

### 2.1 Direction Mismatch Bucket (biggest single loss source)

| Index | Sector | Signal       | V6.1 Trades | V6.1 Net PnL | V6.2 Trades | V6.2 Net PnL |
| ----- | ------ | ------------ | ----------- | ------------ | ----------- | ------------ |
| DOWN  | UP     | UP (LONG)    | 364         | **−251,247** | 324         | **−80,755**  |
| UP    | DOWN   | DOWN (SHORT) | 280         | +24,281      | 244         | **−41,369**  |
| DOWN  | DOWN   | UP (LONG)    | 23          | −9,792       | 16          | −2,099       |

**Problem:** The sector bias says LONG (score ≥ +10), the stock signal is LONG,
but the broad index (NIFTY 50) is falling on the day. 364 trades in V6.1 lost
₹251K — that single bucket accounts for 50%+ of all gross losses. In V6.2 it is
still the largest loser at −₹81K.

**Root cause:** `nifty_pct` flows into the composite score as a _weight_ (× 30) but
the bias threshold (±10) is so loose that breadth alone can override it. A net
breadth of +0.25 contributes +10 to the composite — enough to flip NEUTRAL→LONG
even when Nifty is red.

## 3 Proposed Changes — Sector Scoring Table

### Change S1: Tighten Bias Threshold ±10 → ±20

| Parameter       | Current         | Proposed            |
| --------------- | --------------- | ------------------- |
| LONG threshold  | composite ≥ +10 | composite ≥ **+20** |
| SHORT threshold | composite ≤ −10 | composite ≤ **−20** |

**Why:** A breadth of +0.25 × weight 40 = +10 already triggers LONG. This is
too easy. Raising to ±20 requires _two_ favorable components (e.g., breadth +0.30
AND nifty_pct positive) before a bias fires.

**Impact estimate:** This will eliminate marginal/ambiguous sector calls. Sectors
that barely cross ±10 are the ones that produce the DOWN/UP/UP mismatch bucket.

### Change S2: Add Index-Sector Agreement Multiplier

Currently `nifty_pct` enters the composite as an additive weight. Add a
**multiplicative damper** after computing the raw score:

```
if sign(composite_score) != sign(nifty_pct) and abs(nifty_pct) > 0.3:
    composite_score *= 0.5   # Halve conviction when index disagrees
```

| Condition                                       | Multiplier      |
| ----------------------------------------------- | --------------- |
| Sector and Index same direction                 | 1.0 (no change) |
| Sector and Index disagree, \|nifty_pct\| > 0.3% | **0.5**         |
| Nifty flat (within ±0.3%)                       | 1.0 (no change) |

**Why:** This directly targets the DOWN/UP/UP bucket. A sector may be strong
relative to peers, but if Nifty is falling >0.3%, the absolute probability of
LONG trades working drops sharply.

### Change S3: Reduce Breadth Weight 40 → 25, Increase Nifty Weight 30 → 40

| Weight      | Current | Proposed |
| ----------- | ------- | -------- |
| structural  | 3       | 3        |
| shortterm   | 10      | 10       |
| intraday    | 20      | 20       |
| **breadth** | **40**  | **25**   |
| **nifty**   | **30**  | **40**   |

**Why:** Breadth (above/below VWAP count) is noisy early in the day and can be
dominated by 1–2 stocks in small-cap-heavy sectors. Giving Nifty more weight
forces the composite to respect the broad market direction — the single strongest
predictor of intraday trade success per the direction matrix.

### Change S4: Dynamic Sector Selection — Require Minimum Score Magnitude

Currently `select_top_n` picks top 3 or top 5 based on spread. Add a floor:

```python
MIN_SECTOR_SCORE_MAGNITUDE = 15.0  # Do NOT select if |composite| < 15
```

Skip any sector below this floor even if it's in the top N. This prevents
NEUTRAL-leaning sectors from being selected just because they happen to be the
"least neutral."

## 4 Proposed Changes — Signal Grading Table

### Change G1: Add Index Direction as a Grading Input (Demotion Filter)

After computing the 10-point score, apply a **post-grade demotion**:

```python
# If signal direction opposes index by more than 0.3%
if direction == "LONG" and nifty_pct < -0.3:
    if grade in ("A", "B"):
        grade = "C"  # Demote — do not trade LONG on red-index day
    elif grade == "A+":
        grade = "A"  # Downgrade A+ to A (reduced size, still allowed)

if direction == "SHORT" and nifty_pct > 0.3:
    if grade in ("A", "B"):
        grade = "C"
    elif grade == "A+":
        grade = "A"
```

| Signal Dir | Nifty %      | Original Grade | New Grade        |
| ---------- | ------------ | -------------- | ---------------- |
| LONG       | < −0.3%      | A+             | A (reduced size) |
| LONG       | < −0.3%      | A              | **C (blocked)**  |
| SHORT      | > +0.3%      | A+             | A (reduced size) |
| SHORT      | > +0.3%      | A              | **C (blocked)**  |
| Any        | within ±0.3% | no change      | no change        |

**Why:** This is the most targeted fix for the DOWN/UP/UP bucket. Of those 324
trades in V6.2, most had grade A (score 7–8). Demoting them to C prevents entry.
Only A+ (score ≥ 9, very high conviction) is allowed to trade against the index,
and even then at reduced size (A multiplier 0.85 instead of A+ 1.00).

### Change G2: Raise A-Grade Threshold 7 → 8

| Grade | Current Threshold | Proposed Threshold |
| ----- | ----------------- | ------------------ |
| A+    | ≥ 9               | ≥ 9 (no change)    |
| **A** | **≥ 7**           | **≥ 8**            |
| B     | ≥ 4               | ≥ 4 (no change)    |

**Why:** Currently 7/10 qualifies as A-grade. Many of these are "just barely
qualified" signals — HMA aligned (3) + adequate RVOL (1) + StochRSI neutral (1) +
top 5 sector (1) + good spread (1) = 7 = grade A. That combination carries
little real conviction. Raising to 8 means you need at least one "strong"
component (strong RVOL, extreme StochRSI, or top 3 sector).

**Trade reduction estimate:** Roughly 15–25% of current A-grade signals should
downgrade to B (blocked from entry), reducing trade count by ~300–500 trades.

### Change G3: Tighten StochRSI Neutral Zone

Current logic gives 1 point for StochRSI in 20–80 range. Tighten:

| StochRSI Condition               | Current Pts | Proposed Pts |
| -------------------------------- | ----------- | ------------ |
| LONG + K < 20 (extreme confirm)  | 2           | 2            |
| SHORT + K > 80 (extreme confirm) | 2           | 2            |
| LONG + K in 20–40                | 1           | **1.5**      |
| SHORT + K in 60–80               | 1           | **1.5**      |
| K in 40–60 (dead zone)           | 1           | **0**        |
| LONG + K > 80 (divergence)       | DQ          | DQ           |
| SHORT + K < 20 (divergence)      | DQ          | DQ           |

**Why:** StochRSI of 50 (completely neutral) currently scores the same as
StochRSI of 25 (for a LONG — much more confirming). Dead-zone StochRSI should
give zero points, not a free point.

### Change G4: Add RVOL Bonus Tier

| RVOL Level                     | Current Pts  | Proposed Pts |
| ------------------------------ | ------------ | ------------ |
| Below threshold                | DQ (grade C) | DQ (grade C) |
| Threshold to threshold+0.3     | 1            | 1            |
| threshold+0.3 to threshold+0.8 | 2            | 2            |
| **> threshold + 0.8**          | 2            | **2.5**      |

**Why:** Very high RVOL (e.g., >2.0) is a genuinely different signal — it
indicates institutional flow. A small bonus helps these signals reach A+ more
easily.

## 5 Proposed Changes — Time & Regime Filters

### Change T1: Delay Entry Start 09:25 → 10:15 (or A+ only before 10:15)

**Option A — Hard delay:** Set `ENTRY_START_TIME = time(10, 15)`

**Option B — Grade gate (preferred):** Allow only A+ signals before 10:15.

```python
if ts.time() < time(10, 15) and signal.grade != "A+":
    entry_decision = "EARLY_GRADE_BLOCK"
```

**Why:** The OPEN bucket (09:25–10:30) generates the most trades but the worst
PnL/trade in every version. The first 45 minutes after market open have
unreliable breadth, spreads are wider, and VWAP hasn't stabilized. Delaying
entry or requiring extreme conviction removes the noise trades.

### Change R1: Regime-Specific Position Limits

| Regime      | Current Max Positions | Proposed Max Positions | Grade Gate       |
| ----------- | --------------------- | ---------------------- | ---------------- |
| TRENDING    | 6                     | 6                      | A+ and A allowed |
| NEUTRAL     | 6                     | 6                      | A+ and A allowed |
| MEAN_REVERT | 6                     | **4**                  | **A+ only**      |
| EXTREME     | 6                     | **3**                  | **A+ only**      |

**Why:** MEAN_REVERT is net-negative (−₹974) and EXTREME has high variance.
Cutting positions and requiring A+ in these regimes confines the strategy to
highest-conviction opportunities when the market is hardest to read.

### Change R2: First-Trade Loss → Reduce Remaining Day Size

After the first trade of the day closes as a loss, apply a **day-level size
reduction** of 0.5× to all subsequent trades that day:

```python
if first_trade_closed_loss:
    day_risk_multiplier *= 0.5
```

**Why:** The first-trade-effect correlation is 0.55. If the first trade loses,
the probability of a losing day is 68.5%. Reducing size limits damage on these
days. This is not a kill switch (still allows trading) but a defensive posture.

## 7 Implementation Notes

All changes should be implemented inside `sector_engine_v6.2.py` as **self-

(protecting the production codebase).

Specific locations:

  `_update_sector_scores()`.
- **G1, G2, G3, G4:** Add post-processing after `self.stock_grader.calculate_grade()`
  in `_scan_tradeable_stocks()`.
- **T1:** Add time check in `_scan_tradeable_stocks()` or `_process_entry()`.
